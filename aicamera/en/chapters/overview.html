Chapter 01 · System Architecture, Dual-NPU SW Stack & Agent Flow

Heterogeneous Edge Camera & System Bottlenecks

When running neural ISPs and generative vision models in real time on modern edge camera systems, the first wall you hit is not a lack of NPU TOPS, but inter-chip data movement and memory bandwidth. This chapter examines why signal representation must change at the sensor–host boundary, how the repository's three research tracks (LSP · Software ISP · Universal CFA) solve this problem, and how the IMX500(.rpk) · Hailo-8(.hef) cross-compilation pipeline and Antigravity agent workflow operate.

  • Verify through equations and an interactive simulator how MIPI CSI-2 DMA serialization latency (52.91 ms) and memory contention during uncompressed frame transfer cap overall throughput (14.9 FPS).
  • Understand the hardware topology and memory constraints spanning Sony IMX500 (sensor NPU, .rpk) → MIPI CSI-2 → Raspberry Pi 5 (CPU/Vulkan GPU) + Hailo-8 (host NPU, .hef) → Workstation (RTX 5060 Ti).
  • Compare the structural differences between pixel-domain optimization (Software ISP · Halide kernel fusion) and latent-domain split inference (LSP · Universal CFA).
  • Master the software stack that converts PyTorch models into IMX500 .rpk (NCHW→NHWC transposition, real-frame MCT quantization) and Hailo-8 .hef (ONNX patching, real-distribution tensor PTQ) atop a 4-Tier isolated Python virtual environment hierarchy.
  • Learn the closed-loop agent workflow composed of the FastMCP server (aicamera_mcp_server.py), remote bridge (rpi_remote.py), 7 slash skills, and 10 specialist roles.

Why Split Sensor–Host Inference: MIPI CSI-2 Bandwidth & Serialization Bottlenecks

Conventional camera pipelines start after the sensor converts light into digital values by shipping the entire uncompressed pixel frame across the MIPI CSI-2 serial bus into the host SoC's DRAM. Even if you attach a fast NPU (e.g., a 26 TOPS Hailo-8) to the host, if the frame takes too long to arrive in host memory and be extracted by the driver, the overall frame rate remains locked to bus latency.

On our physical testbed (Sony IMX500 + Raspberry Pi 5 + Hailo-8), measuring the IDENTITY baseline—which forwards an unmodified \(512\times 512\) 3-channel FP32 frame (3072 KB) over the metadata path—shows that host-side tensor extraction (bus_ms) alone takes 52.91 ms, capping camera-synchronized throughput at 14.9 FPS. By contrast, when the in-sensor NPU reduces spatial resolution by \(s_A=8\times\) and emits only a 4-channel latent feature \(r\) (64 KB, \(48\times\) reduction), bus extraction drops to 2.90 ms, reaching the camera's physical ceiling of 30.0 FPS.

Architectural Comparison of the 3 Research Tracks (LSP · Software ISP · Universal CFA)

This repository comprises three research projects that break through heterogeneous edge camera bottlenecks at different layers. All three share the same physical testbed and remote orchestration chain, but differ sharply in what the sensor emits and how the host reconstructs it.

Project 1 · lsp/HW Measured

Latent Signal Processing

Splits the encoder across the sensor NPU (Stage A, .rpk) and host NPU (Stage B, .hef) to transmit only a 64 KB tensor r, driving both a real-time preview (30.0 FPS) and ZSL generative capture from the standard SD VAE latent space ẑ.

Project 2 · hdrnet/HW Measured

Software ISP & Halide

Implements a 10-stage C99 reference ISP + 3A control loop, and applies Verified Lifting and Halide kernel fusion (Tier 3 CPU NEON · Tier 4 Vulkan DMA-BUF) to cut per-12MP-frame DRAM traffic by 13.8× and process frames in 128.78 ms.

Canonical source: hdrnet/README.md · Go to Chapter 03 →

Project 3 · universal_cfa/Simulation

Universal CFA

Connects high-megapixel mobile sensors with clustered CFAs (Bayer 2×2 · Tetracell 4×4 · Hexadecacell 8×8) directly to a single frozen host translator (\(\mathcal{T}_B\)) using only a phase-aware PixelUnshuffle compressor without dedicated remosaicing hardware.

SW Stack & Dual-NPU Cross-Compilation Pipeline (.rpk / .hef)

To run the heterogeneous edge camera pipeline on real hardware, a split model trained in a single PyTorch checkpoint must be cross-compiled to two completely different hardware targets: Sony IMX500 sensor NPU firmware (.rpk) and Hailo-8 host NPU executable binaries (.hef). In parallel, the Software ISP track compiles C99 reference code into Halide AOT shared libraries (.so) and Vulkan shaders.

4-Tier Python Virtual Environment Isolation Architecture

Modern PyTorch GPU wheels, the Sony IMX500 converter (Keras 2 only), and the Hailo Dataflow Compiler (locked to Python 3.10 C-extensions) have mutually incompatible framework versions and Protobuf/ONNX dependencies. Therefore, this project strictly isolates three virtual environments on the Workstation (WSL2, RTX 5060 Ti) plus the system environment on the Raspberry Pi 5, exchanging artifacts across environments exclusively through framework-agnostic NumPy archives (.npz / .npy) and standard .onnx files (export_stagea_weights.py, generate_hailo_calib.py).

1) Sony IMX500 .rpk Conversion Essentials

Stage A deployed on the in-sensor NPU is a pure feed-forward stack of Conv2d(k=4, s=2) → LeakyReLU(0.1) (encoder.py:44). Cross-compilation requires strict adherence to three engineering rules (export_stagea_weights.py, convert_v2_imx500.py, compile_all_imx500.py):

  1. Keras Version Bridge (.npz): A .keras file saved by Keras 3 in py311_train cannot be loaded by Keras 2 (tf-keras) in ~/aicamera/venv. Thus export_stagea_weights.py dumps pure NumPy arrays (w0..w2, b0..b2) and a JSON layer specification.
  2. NCHW → NHWC 4D Kernel Transposition: When injecting a PyTorch convolution weight tensor \(\mathbf{W}_{\text{PyTorch}} \in \mathbb{R}^{C_{\text{out}} \times C_{\text{in}} \times k_H \times k_W}\) into a Keras 2 NHWC convolution layer, the axes must be transposed in order (2, 3, 1, 0).
  3. Domain-Aligned Empirical Calibration: Feeding synthetic DIV2K images into Sony MCT (mct.ptq.keras_post_training_quantization) causes quantization saturation due to mismatch with the real IMX500 sensor ISP exposure and black-level distribution. We always calibrate with real indoor camera captures stored in docs/imx500_calib_frames/*.png.
$$\mathbf{W}_{\text{Keras}}[k_H, k_W, c_{\text{in}}, c_{\text{out}}] = \mathbf{W}_{\text{PyTorch}}[c_{\text{out}}, c_{\text{in}}, k_H, k_W], \qquad \text{np.transpose}(\mathbf{W},\; (2, 3, 1, 0))$$ (1.4) PyTorch→Keras Kernel Transposition

Compilation report (model_quantized_MemoryReport.json): SA8 physical weight size is 2.22KB, and peak runtime memory is 2.76MB / 8.00MB (35%), achieving Fit In Chip: true.

# [Step 1 · ~/py311_train] PyTorch checkpoint → version-agnostic .npz export
~/py311_train/bin/python lsp/src/train/export_stagea_weights.py \
  --ckpt lsp/src/train/runs/enc_sa8_c4_div2k_20k/last.pt \
  --out  lsp/aicamera-models/stageA_sa8_c4_weights.npz

# [Step 2 · ~/aicamera/venv] Keras 2 rebuild + MCT PTQ + imxconv-tf packaging (SA8·SA4·SA2 batch)
~/aicamera/venv/bin/python lsp/src/server/compile_all_imx500.py --height 512 --width 512

2) Hailo-8 .hef & Halide .so Compilation Essentials

Stage B and the TAESD_ft decoder running on the host Hailo-8 NPU are compiled via ClientRunner(hw_arch="hailo8") in hailo_dataflow_compiler (export_decoder_onnx.py, generate_hailo_calib.py, compile_all_stgb_hef.py, compile_taesd_hef.py):

  1. ONNX Legacy Export & kernel_shape Patching: PyTorch's new dynamo=True exporter omits certain operator attributes, while legacy export with padding="same" records only auto_pad and omits kernel_shape. export_decoder_onnx.py exports with dynamo=False, opset=11 and then traverses every Conv node in the ONNX graph to directly patch kernel_shape=[kH, kW] from the weight tensor dimensions.
  2. Per-Network Real-Distribution Calibration Tensors: The input to Stage B is not a 0–255 image but the bus tensor \(\mathbf{r} = \mathcal{E}_A(\mathbf{x})\) emitted by Stage A, and the input to TAESD_ft is the latent tensor \(\hat{\mathbf{z}} = \mathcal{E}_B(\mathbf{r})\). generate_hailo_calib.py extracts the exact NHWC FP32 tensors (calib_bus_*.npy, calib_latent_*.npy) each network will encounter and feeds them to runner.optimize().
  3. Halide AOT Cross-Compilation (Software ISP): For the 10-stage pipeline in Chapter 03, build_openisp_halide.py executes the Halide generator to compile C99-callable libopenisp_halide.so and Vulkan Compute backends.
# [Step 1 · ~/py311_train] Export Stage B ONNX and generate real-distribution calibration tensors (.npy)
~/py311_train/bin/python lsp/src/train/export_decoder_onnx.py \
  --ckpt lsp/src/train/runs/enc_sa8_c4_div2k_20k/last.pt \
  --out  lsp/hailo-models/enc_stgb_sa8_c4.onnx --height 64 --width 64
~/py311_train/bin/python lsp/src/train/generate_hailo_calib.py \
  --ckpt lsp/src/train/runs/enc_sa8_c4_div2k_20k/last.pt --height 512 --width 512 \
  --out-bus lsp/hailo-models/calib_bus_sa8_c4.npy --out-latent lsp/hailo-models/calib_latent_sa8_c4.npy

Agent Workflow · MCP Server · Remote Edge Orchestration

This repository is architected so that researchers and AI agents (Antigravity) can execute the entire cycle—model training → quantization & compilation → remote deployment & physical benchmarking on Raspberry Pi 5 → drift verification → documentation & slide synchronization—in an automated closed loop (GEMINI.md, tools/aicamera_mcp_server.py, tools/rpi_remote.py).

Key Takeaways

  1. Streaming high-resolution uncompressed frames from an edge camera makes MIPI CSI-2 DMA serialization latency (52.91 ms @ 512²) the dominant bottleneck, capping frame rate at 14.9 FPS regardless of host NPU speed.
  2. LSP (Project 1) asymmetrically splits the encoder across the sensor NPU (Stage A, 5,924 params) and host NPU (Stage B, 595K params), shrinking bus payload by 48× (64 KB, 2.90 ms) to achieve a 30.0 FPS live viewfinder and ZSL generative capture.
  3. Software ISP (Project 2) fuses a 10-stage C99 pipeline into a single Halide kernel (Tier 3) and applies VideoCore VII DMA-BUF zero-copy (Tier 4), cutting per-12MP-frame DRAM traffic by 13.8× (811 → 59 MB).
  4. Universal CFA (Project 3) processes Bayer (2×2), Tetracell (4×4), and Hexadecacell (8×8) clustered CFAs with an in-sensor phase-aware PixelUnshuffle compressor that shares a single frozen host translator (\(\mathcal{T}_B\)).
  5. Dual-NPU SW Stack & Agent Workflow compiles .rpk/.hef binaries via NCHW→NHWC kernel transposition and real-distribution calibration across 4-Tier isolated Python virtualenvs (py311_train, venv, py310, RPi 5), automating physical benchmarks and drift guarding through the FastMCP server (tools/aicamera_mcp_server.py) and remote bridge (tools/rpi_remote.py).
