Chapter 01 · System Architecture, Dual-NPU SW Stack & Agent Flow

이종 엣지 카메라와 시스템 병목

현대 엣지 카메라 시스템에서 뉴럴 ISP와 생성형 비전 모델을 실시간으로 구동할 때 가장 먼저 마주치는 벽은 연산기(NPU)의 TOPS 부족이 아니라 칩 간 데이터 이동과 메모리 대역폭입니다. 이 장에서는 왜 센서–호스트 경계에서 신호 표현을 바꿔야 하는지, 본 저장소의 3대 연구 트랙(LSP · Software ISP · Universal CFA)이 이 문제를 어떻게 해결하는지, 그리고 IMX500(.rpk) · Hailo-8(.hef) 크로스 컴파일 파이프라인과 Antigravity 에이전트 워크플로가 어떻게 동작하는지 살펴봅니다.

  • 비압축 프레임 전송 시 발생하는 MIPI CSI-2 DMA 직렬화 지연(52.91 ms)과 메모리 경합이 전체 처리량(14.9 FPS)을 제한하는 메커니즘을 수식과 시뮬레이터로 확인한다.
  • Sony IMX500(센서 NPU, .rpk) → MIPI CSI-2 → Raspberry Pi 5(CPU/Vulkan GPU) + Hailo-8(호스트 NPU, .hef) → Workstation(RTX 5060 Ti)으로 이어지는 하드웨어 토폴로지와 메모리 제약을 이해한다.
  • 픽셀 도메인 최적화(Software ISP · Halide 커널 융합)와 잠재 도메인 분할 추론(LSP · Universal CFA)의 구조적 차이를 비교한다.
  • 4-Tier Python 가상환경 격리 구조 위에서 PyTorch 모델을 IMX500 .rpk(NCHW→NHWC 전치, 실측 프레임 MCT 양자화)와 Hailo-8 .hef(ONNX 패치, 실분포 텐서 PTQ)로 변환하는 SW 스택을 마스터한다.
  • FastMCP 서버(aicamera_mcp_server.py), 원격 브리지(rpi_remote.py), 7개 슬래시 스킬 및 10개 전문 역할로 구성된 닫힌 루프 에이전트 워크플로를 익힌다.

왜 센서–호스트 분할인가: MIPI CSI-2 대역폭과 직렬화 병목

전통적인 카메라 파이프라인은 센서가 빛을 디지털 값으로 바꾼 뒤, 비압축 픽셀 프레임 전체를 MIPI CSI-2 직렬 버스를 통해 호스트 SoC의 DRAM으로 넘기는 것에서 출발합니다. 호스트에 아무리 빠른 NPU(예: 26 TOPS급 Hailo-8)를 달아도, 프레임이 호스트 메모리에 도착하고 드라이버가 이를 추출하는 시간이 길면 전체 프레임레이트는 버스 지연에 묶입니다.

우리의 물리 테스트베드(Sony IMX500 + Raspberry Pi 5 + Hailo-8)에서 \(512\times 512\) 해상도의 3채널 FP32 프레임(3072 KB)을 가공 없이 메타데이터 경로로 전달하는 IDENTITY 기준선을 측정하면, 호스트 측 텐서 추출 시간(bus_ms)만 52.91 ms가 걸려 카메라 동기 처리량이 14.9 FPS에 머뭅니다. 반면 센서 내부 NPU에서 공간 해상도를 \(s_A=8\)배 줄인 4채널 잠재 특징 \(r\)(64 KB, 48× 축소)만 내보내면 버스 추출 시간이 2.90 ms로 줄어 카메라 물리 상한인 30.0 FPS에 도달합니다.

3대 연구 트랙 아키텍처 비교 (LSP · Software ISP · Universal CFA)

이 저장소는 이종 엣지 카메라의 병목을 서로 다른 층위에서 돌파하는 세 가지 연구 프로젝트로 구성됩니다. 각 프로젝트는 동일한 하드웨어 테스트베드와 원격 제어 체인을 공유하지만, 센서에서 무엇을 내보내고 호스트에서 어떻게 복원하는가에서 뚜렷한 차이를 가집니다.

Project 1 · lsp/HW 실측

Latent Signal Processing

인코더를 센서 NPU(Stage A, .rpk)와 호스트 NPU(Stage B, .hef)로 분할해 64 KB 텐서 r만 전송하고, 표준 SD VAE 잠재 공간 ẑ로 실시간 프리뷰(30.0 FPS)와 ZSL 생성형 캡처를 동시에 구동합니다.

정본: lsp/README.md · Chapter 02 이동 →

Project 2 · hdrnet/HW 실측

Software ISP & Halide

10단계 C99 레퍼런스 ISP + 3A 제어 루프를 구현하고, Verified Lifting과 Halide 커널 융합(Tier 3 CPU NEON · Tier 4 Vulkan DMA-BUF)으로 12MP 프레임당 DRAM 트래픽을 13.8× 줄여 128.78 ms에 처리합니다.

정본: hdrnet/README.md · Chapter 03 이동 →

Project 3 · universal_cfa/시뮬레이션

Universal CFA

고화소 모바일 센서의 군집형 CFA(Bayer 2×2 · Tetracell 4×4 · Hexadecacell 8×8)에서 별도 리모자이킹 하드웨어 없이 위상 인식 PixelUnshuffle 압축기만으로 단일 고정 호스트 번역기(\(\mathcal{T}_B\))에 직결합니다.

이종 하드웨어 토폴로지와 메모리 계층

실험 플랫폼은 네 개의 연산 노드가 직렬·병렬로 결합된 이종(heterogeneous) 구조입니다. 각 칩은 허용하는 연산자 집합, 정밀도(INT8 vs FP16/FP32), 온칩 메모리 크기가 완전히 다르므로 하드웨어 제약을 먼저 이해해야 모델과 컴파일 스케줄을 설계할 수 있습니다.

SW 스택 & Dual-NPU 크로스 컴파일 파이프라인 (.rpk / .hef)

이종 엣지 카메라 파이프라인을 실제로 구동하려면 단일 PyTorch 체크포인트에서 학습된 분할 모델을 Sony IMX500 센서 NPU 펌웨어(.rpk)와 Hailo-8 호스트 NPU 실행 바이너리(.hef)라는 전혀 다른 두 하드웨어 타깃으로 각각 크로스 컴파일해야 합니다. 또한 Software ISP 트랙은 C99 레퍼런스 코드를 Halide AOT 정적 라이브러리(.so) 및 Vulkan 셰이더로 컴파일합니다.

4-Tier Python 가상환경 격리 아키텍처

PyTorch 최신 GPU 휠, Sony IMX500 변환기(Keras 2 전용), Hailo 데이터플로 컴파일러(Python 3.10 C-확장 고정)는 프레임워크 버전과 Protobuf/ONNX 의존성이 서로 충돌합니다. 따라서 본 프로젝트는 Workstation(WSL2, RTX 5060 Ti)의 3개 격리 가상환경과 Raspberry Pi 5의 시스템 환경을 명확히 분리하고, 환경 간 데이터 교환은 프레임워크 독립적인 순수 NumPy 아카이브(.npz / .npy)와 표준 .onnx 파일로만 수행합니다(export_stagea_weights.py, generate_hailo_calib.py).

1) Sony IMX500 .rpk 변환 핵심 디테일

센서 내장 NPU에 올라가는 Stage A는 Conv2d(k=4, s=2) → LeakyReLU(0.1)의 순수 피드포워드 구조입니다(encoder.py:44). 크로스 컴파일 시 다음 세 가지 엔지니어링 규칙을 반드시 지켜야 합니다(export_stagea_weights.py, convert_v2_imx500.py, compile_all_imx500.py):

  1. Keras 버전 브리지 (.npz): py311_train의 Keras 3에서 저장한 .keras 파일은 ~/aicamera/venv의 Keras 2(tf-keras)에서 열리지 않습니다. 따라서 export_stagea_weights.py가 순수 NumPy 배열(w0..w2, b0..b2)과 JSON 레이어 스펙으로 덤프합니다.
  2. NCHW → NHWC 4차원 커널 전치: PyTorch 합성곱 가중치 텐서 \(\mathbf{W}_{\text{PyTorch}} \in \mathbb{R}^{C_{\text{out}} \times C_{\text{in}} \times k_H \times k_W}\)를 Keras 2의 NHWC 합성곱 커널 규격으로 주입할 때 축 순서를 반드시 (2, 3, 1, 0)으로 전치해야 합니다.
  3. 도메인 정렬 실측 캘리브레이션: Sony MCT(mct.ptq.keras_post_training_quantization) 실행 시 합성 DIV2K 이미지를 넣으면 실제 IMX500 센서 ISP의 노출·블랙레벨 분포와 어긋나 양자화 포화(saturation)가 발생합니다. 반드시 docs/imx500_calib_frames/*.png에 수집된 실제 실내 카메라 캡처 프레임을 사용합니다.
$$\mathbf{W}_{\text{Keras}}[k_H, k_W, c_{\text{in}}, c_{\text{out}}] = \mathbf{W}_{\text{PyTorch}}[c_{\text{out}}, c_{\text{in}}, k_H, k_W], \qquad \text{np.transpose}(\mathbf{W},\; (2, 3, 1, 0))$$ (1.4) PyTorch→Keras 커널 전치

컴파일 결과 리포트(model_quantized_MemoryReport.json): SA8 모델 가중치 물리 크기는 2.22KB, 런타임 피크 메모리는 2.76MB / 8.00MB (35%)로 Fit In Chip: true를 달성합니다.

2) Hailo-8 .hef 및 Halide .so 컴파일 디테일

호스트의 Hailo-8 NPU에서 동작하는 Stage B와 TAESD_ft 디코더는 hailo_dataflow_compiler의 ClientRunner(hw_arch="hailo8")로 컴파일합니다(export_decoder_onnx.py, generate_hailo_calib.py, compile_all_stgb_hef.py, compile_taesd_hef.py):

  1. ONNX Legacy Export & kernel_shape 패치: PyTorch의 신규 dynamo=True 내보내기는 일부 연산자 속성을 누락하며, padding="same" 사용 시 레거시 내보내기가 auto_pad만 기록하고 kernel_shape를 생략합니다. export_decoder_onnx.py는 dynamo=False, opset=11로 내보낸 뒤 ONNX 그래프의 모든 Conv 노드를 순회하며 가중치 텐서 차원에서 kernel_shape=[kH, kW] 속성을 직접 패치합니다.
  2. 네트워크별 실분포 캘리브레이션 텐서 생성: Stage B의 입력은 0~255 이미지가 아니라 Stage A가 출력한 버스 텐서 \(\mathbf{r} = \mathcal{E}_A(\mathbf{x})\)이며, TAESD_ft의 입력은 잠재 텐서 \(\hat{\mathbf{z}} = \mathcal{E}_B(\mathbf{r})\)입니다. generate_hailo_calib.py가 각 네트워크가 실제로 보게 될 NHWC FP32 텐서(calib_bus_*.npy, calib_latent_*.npy)를 추출해 runner.optimize()에 공급합니다.
  3. Halide AOT 크로스 컴파일 (Software ISP): 3장 Software ISP의 10단계 파이프라인은 build_openisp_halide.py가 Halide 생성기를 실행해 C99 호출 규격의 libopenisp_halide.so와 Vulkan Compute 백엔드로 컴파일합니다.

에이전트 워크플로 (Agent Flow) · MCP 서버 · 원격 엣지 오케스트레이션

이 저장소는 연구자와 AI 에이전트(Antigravity)가 모델 학습 → 양자화·컴파일 → Raspberry Pi 5 원격 배포 및 물리 벤치마크 → 드리프트 검증 → 문서·슬라이드 동기화의 전 과정을 닫힌 루프(closed-loop)로 자동 수행하도록 설계되어 있습니다(GEMINI.md, tools/aicamera_mcp_server.py, tools/rpi_remote.py).

MCP 서버 (aicamera_mcp_server.py) 노출 도구

에이전트가 학습 실행이나 하드웨어 측정 시 경로·인자 오류를 일으키지 않도록, tools/aicamera_mcp_server.py는 표준 Model Context Protocol(FastMCP) 위에서 7개의 결정론적 도구를 노출합니다:

MCP 도구 이름동작 및 안전 게이트
detect_environment()호스트가 rpi(IMX500 + hailortcli 존재)인지 server(GPU/WSL2)인지 자동 판별
run_benchmark(modes, n_frames)물리 벤치마크 실행 후 rpi_table1_bench_results.json과 자동 비교
read_status_table()정본 벤치마크 JSON(rpi_table1_bench_results.json)의 전체 모드 측정치를 즉시 반환
diff_bench(fresh, canonical)\(\lvert\Delta\text{FPS}\rvert \ge 0.3\) 또는 \(\lvert\Delta t_{\text{total}}\rvert \ge 1.0\text{ ms}\) 드리프트 발생 시 drifted=true 경고
list_train_configs()lsp/src/train/configs/*.yaml의 유효한 학습 설정 목록 조회

핵심 정리

  1. 엣지 카메라에서 고해상도 비압축 프레임을 그대로 전송하면 MIPI CSI-2 DMA 직렬화 지연(52.91 ms @ 512²)이 지배적 병목이 되어 호스트 NPU 성능과 무관하게 프레임레이트가 14.9 FPS에 묶인다.
  2. LSP(Project 1)는 인코더를 센서 NPU(Stage A, 5,924 params)와 호스트 NPU(Stage B, 595K params)로 비대칭 분할해 버스 페이로드를 48×(64 KB, 2.90 ms) 줄이고 30.0 FPS 실시간 뷰파인더와 ZSL 생성형 캡처를 달성한다.
  3. Software ISP(Project 2)는 10단계 C99 파이프라인을 Halide 단일 커널로 융합(Tier 3)하고 VideoCore VII DMA-BUF 제로카피(Tier 4)를 적용해 12MP 프레임당 DRAM 트래픽을 13.8×(811 → 59 MB) 절감한다.
  4. Universal CFA(Project 3)는 Bayer(2×2)·Tetracell(4×4)·Hexadecacell(8×8) 군집형 CFA를 센서 내 위상 인식 PixelUnshuffle 압축기로 처리해 단일 고정 호스트 번역기(\(\mathcal{T}_B\))를 공유한다.
  5. Dual-NPU SW 스택 & 에이전트 워크플로는 4-Tier Python 가상환경 격리(py311_train, venv, py310, RPi 5) 위에서 NCHW→NHWC 커널 전치와 실분포 캘리브레이션으로 .rpk/.hef를 컴파일하고, FastMCP 서버(tools/aicamera_mcp_server.py)와 원격 브리지(tools/rpi_remote.py)를 통해 물리 벤치마크 및 드리프트 감시를 자동화한다.
